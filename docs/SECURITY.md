# Security review

Scope:

- authentication and session handling;
- whether correct answers can leak to the client;
- rate limiting on attempts and auth;
- input validation;
- dependency audit;
- Content Security Policy and other browser headers.

Every finding below is fixed and covered by a test or a browser check.

## Checked and sound (no change needed)

- **Sessions.** The cookie holds a 256-bit random token, and the database stores only its SHA-256. The cookie is `HttpOnly` and `SameSite=Lax`, and `Secure` in production. A new session is issued at sign-in and the old one revoked, so session fixation isn't possible. Logout deletes the session on the server.
- **Sign-in.**
  - Magic links are single-use and expire in 15 minutes.
  - The response is always 202, so it never reveals whether an account exists.
  - Post-sign-in redirects accept only same-site paths.
  - Google uses the authorization-code flow with PKCE and `state`, and requires `email_verified`.
  - The admin token is compared in constant time and refused if it's a `change-me` placeholder in production.
- **Authorisation.** Admin, instructor and class-membership checks are on the server, with tests for each. A guest can't hold a role.
- **No correct answers reach the client before grading.** I checked every learner-facing payload: all 100 lessons, Daily Review, checkpoints, mocks, placement, test-out and the live quiz. A question carries only its id, stem, `hasCalculation` and options of `{id, text}`. Correctness, _Why not?_ notes and worked solutions come only from the graded answer:
  - in a lesson Check, the correct option is withheld after a first wrong try;
  - in quizzes, everything waits for the whole submission;
  - in the live quiz, the answer appears only at reveal.

  Option ids are random UUIDs that exist only in the database, so no card or lab config can point at one. Labs carry their own exercise answers by design: they check themselves in the browser, and the server re-verifies goals from the reported state.

- **SQL.** Every query is parameterised. The one dynamic `SET` clause is built from a fixed column map.
- **Errors.** 500 responses say "Internal error"; stack traces go to the log only.
- **CSP in practice.** A sweep of the production build loaded every page and all 188 lab cards: no CSP violations. It also exercised Three.js, the WebAudio recordings, the service worker and answer submission.

## Accepted, with reasons

- `style-src 'unsafe-inline'`: the SVG labs set inline `style` attributes, which a nonce can't cover. With scripts locked down, injected styles can't run code.
- Sessions last 180 days with no idle timeout. That suits a study app used across months, on devices learners own. Logout revokes a session immediately.
- Rate-limit counters live in the API's memory. That's fine with one API instance; behind several, switch the plugin to a Redis store.
- Guest accounts that never sign in are kept, because their progress lives on the server. Pruning old inactive guests is a reasonable later job.

## Configuration

| Variable            | Default                          | Purpose                                                                     |
| ------------------- | -------------------------------- | --------------------------------------------------------------------------- |
| `APP_ORIGIN`        | `http://localhost:3000`          | The public origin: sign-in links, the Google redirect, the Origin check     |
| `ALLOWED_ORIGINS`   | none                             | Extra origins allowed to write (comma-separated)                            |
| `TRUST_PROXY`       | `loopback,linklocal,uniquelocal` | Proxies whose `X-Forwarded-For` is believed                                 |
| `RATE_LIMITS`       | on                               | `off` only for tests and local load sweeps                                  |
| `ADMIN_TOKEN`       | none                             | At least 16 characters; refused if it starts with `change-me` in production |
| `CSP_CONNECT_EXTRA` | none                             | Extra `connect-src` hosts, such as the error-monitoring ingest host         |
| `ENABLE_DEV_PAGES`  | off                              | `1` serves `/dev/components` in production                                  |
