# Accessibility audit (WCAG 2.2 AA)

Phase 2b, Step 26. Target: WCAG 2.2 level AA for every page, every lesson screen and every mode of all 35 labs.

## How it was tested

The scripts are Playwright drivers of real Chrome against `pnpm dev`. Each one walks the content tree, so new lessons and labs are picked up automatically.

| Check                                      | What it covers                                                                                                                                                                                                                                                        | Result                                                                               |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| axe-core 4.10, WCAG 2.0–2.2 A and AA rules | All app pages in light and dark themes. A full lesson: worked example, 11 Check questions each with a wrong-answer _Why not?_ state, and the recap. The checkpoint and mock runners. All 188 lab-step cards (every mode of every lab) in light, and a sample in dark. | 290 audits, 0 violations                                                             |
| Keyboard walk                              | For every lab-step card: Tab from just before the lab until focus leaves it. Each stop must show a visible focus indicator, there must be no trap, and every enabled control must be reached (a radio group counts as one stop).                                      | 188 cards, 796 focus stops, 0 issues                                                 |
| Text alternatives                          | Every SVG and canvas in a lab is either hidden from assistive tech or named. Every slider and meter has an ARIA value. Every lab has a text readout or status region.                                                                                                 | 0 issues after fix 10                                                                |
| SVG text contrast                          | axe doesn't check SVG `<text>`. Each label's fill is resolved through a canvas (oklch tokens become sRGB) and measured against the shape behind it, across all lab cards.                                                                                             | 33 text/background pairs, all AA after fix 5                                         |
| Focus not obscured (2.4.11)                | Tab through lab, lesson and app pages at 1280 × 720 and 360 × 740. No focused element may be fully covered by the sticky footer or pushed off screen.                                                                                                                 | No focus stop obscured                                                               |
| Reflow (1.4.10) and text spacing (1.4.12)  | Every page and lab card at 320 px wide, then again with the WCAG text-spacing overrides. Looks for horizontal scroll, content off the edge, or text clipped by its box.                                                                                               | 296 pages at 320 px: 0 issues. With text spacing: 0 issues, after fixes 9, 11 and 12 |
| Lab requirements                           | Manual review of each lab: text readouts for every meter and value, keyboard controls, visible focus, Morse as dots and dashes, a text equivalent for every audio clip, and colour never the only signal.                                                             | See below                                                                            |

Not done: testing with real screen readers (NVDA, JAWS, VoiceOver, TalkBack). The ARIA patterns are standard (slider, meter, radiogroup, status, img), but a session with each reader is still recommended before launch, especially on the Morse key and the drag-and-drop breadboard.

## Issues found and fixed

| #   | WCAG                      | Issue                                                                                                                                                                                                                                    | Fix                                                                                                                                                                                                                                      |
| --- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 2.5.7 Dragging Movements  | The front-panel `Knob`, used about 35 times across the labs, turned only by drag (or by keyboard). A pointer user who can't drag had no alternative.                                                                                     | Every knob now has − / + buttons beside its value. They are pointer aids, so they're out of the Tab order and hidden from screen readers, which already have the slider.                                                                 |
| 2   | 2.5.7 Dragging Movements  | LAB-29's 3D radiation pattern turned only by drag or arrow keys.                                                                                                                                                                         | Turn left, Turn right, Tilt up and Tilt down buttons. The 2D cuts beside it still carry the same information.                                                                                                                            |
| 3   | 2.2.1 Timing Adjustable   | Mock exams always ran against the clock and auto-submitted at zero.                                                                                                                                                                      | LAB-35 offers **Timed** or **Untimed**. An untimed mock has no countdown and the server accepts its answers at any time (`mock_exam.time_limit_s` is null; migration `0004_untimed_mocks`). It counts toward readiness like a timed one. |
| 4   | 4.1.3 Status Messages     | Nine feedback messages (Interference, Drill, Ohm's Law, Rules, Safety Inspector, Scenario, World Clock and the Hook prediction) inserted their `role="status"` element together with its text, which many screen readers don't announce. | The live regions are always mounted and only their text changes. An empty region takes no space (`[role="status"]:empty { position: absolute }`).                                                                                        |
| 5   | 1.4.3 Contrast (Minimum)  | Analog meter scale labels on an unpowered meter measured 4.08 : 1.                                                                                                                                                                       | The off-state face is dimmed less (72 % instead of 55 % of the face colour): 6.2 : 1.                                                                                                                                                    |
| 6   | 1.4.1 Use of Color        | Two-trace plots (amplifier in and out, rectifier, scope harmonic and phase, RF exposure limit) told the traces apart by colour and dash only, with no visible key.                                                                       | `Plot` draws a legend whenever a series is labelled. Each entry shows the trace's own dash pattern and its name, and every two-trace plot is labelled.                                                                                   |
| 7   | 1.1.1 / 1.3.1 Morse       | The Morse keyer tape showed what you sent only as bars; its dots and dashes were in an `aria-label` that sighted learners never saw.                                                                                                     | A visible line under the tape: "Sent: `.-..`, which reads **L**". The tape itself is now decorative.                                                                                                                                     |
| 8   | 2.4.11 Focus Not Obscured | Tabbing to controls near the bottom of a lab could leave them under the sticky lesson footer (found on the 8.01 Hint button at 1280 × 720).                                                                                              | `scroll-padding-bottom` on the root keeps focused controls clear of the footer.                                                                                                                                                          |
| 9   | 1.4.10 Reflow / 2.4.11    | At 360 px the top navigation was 475 px wide; the theme toggle and part of Sign in were cut off, and focus landed off screen.                                                                                                            | Under 40 rem the nav wraps to its own full-width row with tighter padding.                                                                                                                                                               |
| 10  | 1.1.1 Non-text Content    | LAB-29's WebGL canvas, injected by Three.js, was exposed unnamed inside the named view.                                                                                                                                                  | The canvas is `aria-hidden`; the host element carries the description.                                                                                                                                                                   |

## Lab requirements

| Requirement                           | Status                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Text readout of every meter and value | Every lab renders a `Readouts` list (a `<dl>`) with the same numbers its meters show, and every instrument exposes its value: `Knob` is a slider with `aria-valuetext`, `AnalogMeter` a meter with `aria-valuetext` ("off scale" when overloaded, "not connected" when off), plus `SevenSegment`, `Waterfall` and `Plot` (a named image that states the key numbers). |
| Keyboard controls                     | All controls are native buttons, selects or inputs, or WAI-ARIA sliders with arrow, Page Up/Down, Home and End support. Drag-and-drop (`useDragDrop`) also works by Enter on an item, then Enter on a target. Every control on all 188 lab cards is reached by Tab.                                                                                                   |
| Visible focus                         | A global `:focus-visible` outline uses `--color-focus`, which is redefined for the dark `.shack` lab skin. Breadboard sockets use a thicker lamp-coloured stroke instead. Every focus stop on every lab card shows an indicator.                                                                                                                                      |
| Morse as dots and dashes              | The keyer shows the target and what you sent as text. The copy drill (LAB-10, LAB-09) and the player's audio screen have "Show dots and dashes", and if audio is unavailable the drill shows them automatically.                                                                                                                                                      |
| Text equivalents for audio            | Every interference recording (LAB-33) has a written caption ("What you hear: …") that is always visible. Morse audio has dots and dashes. The sidetone only echoes your own keying, which the tape and text already show.                                                                                                                                             |
| Colour never the only signal          | Answer states carry the words "Correct" and "Your answer". Lab goals start with "Done:". Every feedback message is in words. Resistor bands are named in text. Lesson tiles say Finished or In progress. Readiness says whether you're ready. Plot traces have a dash pattern and a legend.                                                                           |

## Keeping it that way

The audit scripts live outside the repo (Playwright plus axe-core, run against `pnpm dev`). Repeat them before launch and after any change to `packages/ui` or a lab. The rules that matter most in review:

- live regions stay mounted;
- every new instrument exposes its value through ARIA and in `Readouts`;
- every drag has a click alternative;
- colours come from tokens, and a colour change always comes with a word.
